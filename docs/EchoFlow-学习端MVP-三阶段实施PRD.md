# EchoFlow 学习端 MVP 三阶段实施 PRD

更新时间：2026-07-26

版本：v0.1

文档类型：开发落地版 PRD 补充稿

基线文档：`docs/EchoFlow-学习端MVP-PRD.md`

## 1. 文档目的

本文件基于《EchoFlow 学习端 MVP PRD》拆分出三轮实施阶段，用于减少遗漏、及时验证、灵活调整，并降低一次性让 AI 实现过多功能导致的上下文混乱、返工和 bug 积累。

阶段命名按当前协作约定保留为 `P0 / P2 / P3`，不新增 `P1`：

| 阶段 | 名称 | 核心目标 |
| --- | --- | --- |
| P0 | 基石 | 先把账号、真实 API、课程详情、字幕、进度和录音基础链路打稳 |
| P2 | 做功能 | 在 P0 可验证的基础上补齐课程库、练习、生词、收藏、上传等 MVP 核心功能 |
| P3 | 锦上添花 | 做体验、埋点、移动端、反馈、通知和内测运营辅助 |

## 2. 产品基线

### 产品定位

EchoFlow 是面向成人英语自学者的视频影子跟读工具。它把真实英语视频拆成可操作的句子训练单元，通过逐句播放、听写、跟读录音和回听，帮助用户在碎片时间里完成听说练习。

### 目标用户

核心用户是成人英语自学者：

1. 碎片时间学习者：希望快速开始 5 到 15 分钟练习。
2. 听说提升用户：能看懂字幕，但听不清、说不顺。
3. 兴趣内容学习者：想用旅行、日常、文化、职场视频学英语。
4. 自带素材用户：希望把自己的英语视频转成私有课程。

### MVP 北极星指标

完成练习句数。

定义：用户在课程练习页中对一个字幕句完成至少一次有效练习动作后计为完成。有效练习动作包括播放原句、听写提交、录音完成或手动标记完成。MVP 优先使用“完成 cue”作为服务端进度的最小数据单位。

### MVP 非目标

1. 不做发音评分、音素级纠错或口语能力评级。
2. 不做 AI 教练、个性化长周期学习计划或自动复盘报告。
3. 不做公开视频分享、评论、关注或社区。
4. 不做支付、订阅、权益体系或商业化闭环。
5. 不做正式内容 marketplace。
6. 不把录音默认上传云端。MVP 中录音默认保存在本地，仅用于用户即时回听。

## 3. 阶段推进原则

1. 每轮只在上一轮验收通过后进入下一轮。
2. 每轮结束必须能跑通一个可演示闭环，而不是只堆半成品页面。
3. 每轮开始前先读取当轮相关入口、类型、测试和接口，不跨阶段顺手改无关模块。
4. 每轮都先补数据和错误状态，再补视觉细节。
5. 每轮都保留当前可用功能，不为了新功能破坏旧流程。
6. AI 实施时一次只处理一个子系统，例如登录、课程库、练习页、上传，不在同一轮里混改大量无关文件。
7. 所有跨端类型优先放在 `packages/contracts`，业务持久化优先由 API 和数据库承担。
8. 录音仍默认本地保存，不在 P0/P2 引入云端录音上传。

## 4. 阶段总览

| 模块 | P0 基石 | P2 做功能 | P3 锦上添花 |

| 练习 | 字幕 cue、播放位置、进度保存、录音回听基础稳定 | 单句循环、倍速、隐藏视频、听写、生词、字幕标签完整化 | 快捷操作、移动端细节、练习反馈 |

| 数据 | 课程、字幕、进度接入服务端 | 收藏、生词、个人课程、学习记录补齐 | 埋点、摘要、反馈和看板 |
| 验证 | 最小端到端学习闭环 | MVP 核心功能验收 | 内测稳定性和体验验收 |

## 5. P0 基石

### 阶段目标

把学习端从静态演示推进为可验证的真实数据闭环。P0 不追求功能完整，而是确保登录、课程列表、课程详情、字幕 cue、学习进度和录音基础能力稳定。

### 必做范围

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| P0-AUTH-01 | 手机号请求验证码 | 用户输入中国大陆手机号后可请求验证码；开发环境可使用固定验证码 |
| P0-AUTH-02 | 验证码登录 | 登录成功后保存 access token、refresh token 和用户信息 |
| P0-AUTH-03 | 登录态刷新 | access token 过期后可用 refresh token 续期 |
| P0-API-01 | 课程列表接入真实 API | 课程库从 `/api/videos` 获取数据，不再依赖纯静态列表作为唯一来源 |
| P0-API-02 | 课程详情接入真实 API | 练习页从 `/api/lessons/:id` 获取课程详情和 cue |
| P0-API-03 | 学习进度读取 | 进入课程时读取 `/api/progress/:lessonId` 并恢复当前 cue 和位置 |
| P0-API-04 | 学习进度保存 | 切换 cue、完成句子或退出前可更新当前 cue、completedCueIds 和 positionMs |
| P0-PRA-01 | 基础逐句练习 | 支持当前句展示、上一句、下一句、播放/暂停基础交互 |
| P0-REC-01 | 录音与回听基础稳定 | 用户授权麦克风后可录音，停止后可立即回听 |
| P0-REC-02 | 资源释放 | 离开练习页时停止麦克风轨道并释放临时音频 URL |
| P0-ERR-01 | 基础错误状态 | API 失败、课程不存在、字幕为空、麦克风拒绝权限时有明确提示 |

### 暂不做范围

1. 不做收藏、生词、学习记录完整页。
2. 不做真实个人上传处理闭环。
3. 不做发音评分、AI 教练或复杂练习反馈。
4. 不做完整埋点和数据看板。
5. 不做移动端专项打磨，只保证核心流程不阻塞。

### 涉及接口

| 能力 | API |
| --- | --- |
| 请求验证码 | `POST /api/auth/request-code` |
| 验证码登录 | `POST /api/auth/verify-code` |
| 刷新登录态 | `POST /api/auth/refresh` |
| 课程列表 | `GET /api/videos` |
| 课程详情 | `GET /api/lessons/:id` |
| 进度读取 | `GET /api/progress/:lessonId` |
| 进度更新 | `PUT /api/progress/:lessonId` |

### 验收场景

1. 新用户可以用手机号验证码登录。
2. 登录后进入课程库，课程列表来自 API。
3. 用户打开课程，练习页展示服务端课程信息和 cue。
4. 用户切换到第 3 句后退出，再进入时恢复到第 3 句。
5. 用户可以录音并立即回听。
6. 用户拒绝麦克风权限后，仍可继续播放和切换句子。
7. API 失败时页面不白屏，并给出重试或返回路径。

### 技术验证命令

```powershell
pnpm --filter @online-learning/web lint
pnpm --filter @online-learning/web test
pnpm --filter @online-learning/web build
pnpm --filter @online-learning/api test
pnpm --filter @online-learning/api build
```

### AI 实施注意事项

1. 先实现 API 客户端和类型映射，再改页面交互。
2. 登录态处理、课程数据、练习页状态分开提交或分批实现。
3. 不要在 P0 同时重构样式系统。
4. 不要引入大型状态管理库，除非现有代码复杂度已经无法承载。
5. 对录音 Hook 的已有释放逻辑保持谨慎，新增功能必须覆盖卸载和重复启动场景。

## 6. P2 做功能

### 阶段目标

在 P0 数据闭环稳定后，补齐学习端 MVP 的核心功能，让用户能完整完成“找课、练习、收藏、生词、记录、上传生成私有课程”的主流程。

### 必做范围

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| P2-LIB-01 | 首页精选 | 首页展示主推课程、继续学习和课程列表 |
| P2-LIB-02 | 搜索与筛选 | 支持按标题、副标题、创作者、主题搜索，并按难度、主题、口音筛选 |
| P2-LIB-03 | 收藏课程 | 收藏状态可切换、同步和刷新保持 |
| P2-LIB-04 | 继续学习 | 首页展示上次学习课程和进度，一键进入对应 cue |
| P2-PRA-01 | 完整逐句工具 | 支持单句循环、倍速、隐藏视频、字幕标签和听写模式 |
| P2-PRA-02 | 生词加入 | 用户可从当前句加入生词，并在生词本查看 |
| P2-ME-01 | 学习记录 | 展示累计学习时长、完成句数和最近学习课程 |
| P2-UP-01 | 文件校验 | 仅允许视频文件，最大 2GB，未勾选权限确认禁止上传 |
| P2-UP-02 | 预签名上传 | 前端调用 `/api/uploads/presign` 获取上传目标 |
| P2-UP-03 | 任务进度展示 | 个人上传页展示转码、识别、翻译、分句、发布等任务阶段 |
| P2-UP-04 | 私有课程入口 | 任务完成后生成仅本人可见的课程入口 |

### 暂不做范围

1. 不做上传失败后的复杂断点续传。
2. 不做录音云端同步。
3. 不做 AI 发音评分。
4. 不做公开视频发布或分享。
5. 不做正式运营后台深度工作流，只消费必要的课程发布结果。

### 涉及接口

| 能力 | API |
| --- | --- |
| 收藏列表 | `GET /api/favorites` |
| 添加收藏 | `POST /api/favorites/:lessonId` |
| 取消收藏 | `DELETE /api/favorites/:lessonId` |
| 生词列表 | `GET /api/vocabulary` |
| 添加生词 | `POST /api/vocabulary` |
| 删除生词 | `DELETE /api/vocabulary/:id` |
| 上传预签名 | `POST /api/uploads/presign` |
| 任务列表 | `GET /api/jobs` |
| 单任务查询 | `GET /api/jobs/:id` |
| 个人课程列表 | `GET /api/uploads/lessons` |

### 验收场景

1. 用户搜索和筛选课程后，列表结果符合条件。
2. 用户收藏课程后刷新页面，收藏状态仍保留。
3. 用户从首页继续学习卡片进入上次 cue。
4. 用户开启单句循环，当前句结束后自动回到句首。
5. 用户切换倍速后，播放速度符合选中值。
6. 用户进入听写模式，输入内容后可查看答案。
7. 用户将当前句关键词加入生词本，并能在生词本看到。
8. 用户上传未勾选权限确认、非视频文件或超过 2GB 文件时被阻断。
9. 用户成功上传视频后，在个人上传页看到任务进度。
10. 上传任务完成后，用户可以进入生成的私有课程。

```powershell

pnpm --filter @online-learning/web test
pnpm --filter @online-learning/web build
pnpm --filter @online-learning/api lint
pnpm --filter @online-learning/api test
pnpm --filter @online-learning/api build
pnpm --filter @online-learning/worker test
```

### AI 实施注意事项

1. 收藏、生词、上传分别实现，不要在一次修改中混在同一个大组件里。
2. 上传链路先做文件校验和权限确认，再接预签名接口。
3. 任务状态先支持清晰展示，不急着做复杂动效。
4. 练习页新增功能时必须回归 P0 的播放、进度和录音能力。
5. 所有新增接口先补 contracts，再补 API，再接 Web。

## 7. P3 锦上添花

### 阶段目标

在 MVP 核心功能可用后，做内测体验和运营辅助，帮助团队观察数据、收集反馈、定位问题，并提升移动端和异常场景的完成度。

### 必做范围

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| P3-UX-01 | 加载与空状态优化 | 课程库、收藏、生词、上传任务都有清晰 loading、empty、error 状态 |
| P3-UX-02 | 移动端细节 | 手机宽度下登录、课程库、练习页、上传任务无布局阻塞 |
| P3-UX-03 | 失败重试 | 上传失败、任务失败、进度保存失败有可执行的重试入口 |
| P3-DATA-01 | 埋点事件 | 登录、打开课程、播放 cue、完成 cue、录音、收藏、上传、私有课打开有事件记录 |
| P3-DATA-02 | 学习摘要 | 展示累计学习时长、完成句数、最近学习和连续学习 |
| P3-FB-01 | 内测反馈入口 | 用户可提交课程问题、上传问题或学习体验反馈 |
| P3-NOTI-01 | 通知占位 | 通知入口展示系统消息或内测提醒，不影响主流程 |
| P3-OPS-01 | 内测运营辅助 | 支持查看上传成课率、完成练习句数、错误类型等关键数据 |

### 暂不做范围

1. 不做完整 BI 平台。
2. 不做复杂运营活动系统。
3. 不做支付、订阅和会员权限。
4. 不做社区、公开分享和评论。
5. 不做正式生产级推荐算法。

### 涉及接口

| 能力 | 建议 API |
| --- | --- |
| 学习摘要 | `GET /api/me/learning-summary` |
| 上传任务刷新 | `GET /api/uploads/:uploadId/jobs` |
| 反馈提交 | `POST /api/feedback` |
| 埋点上报 | `POST /api/events` |
| 系统消息 | `GET /api/notifications` |

### 验收场景

1. 用户在移动端可以完成登录、找课、练习和查看上传任务。
2. 课程库无结果时，用户可以清楚知道如何调整搜索或筛选。
3. 上传处理失败时，用户能看到失败阶段、原因和重试入口。
4. 用户完成 cue 后产生 `cue_completed` 事件。
5. 用户完成录音后产生 `recording_created` 事件，但录音文件仍默认留在本地。
6. 用户能在个人空间看到累计完成句数和最近学习课程。
7. 用户能提交内测反馈。
8. 通知入口不再只是静态数字，至少能展示系统消息或内测提醒。

### 技术验证命令

```powershell

```

如本阶段涉及可视化或移动端交互调整，额外执行桌面和移动端人工回归。

### AI 实施注意事项

1. P3 不应再改变 P0/P2 的核心数据协议，除非发现真实缺陷。
2. 埋点必须轻量，不阻塞主流程。
3. 反馈入口先做最小可用，不引入复杂工单系统。
4. 移动端优化优先修复阻塞和错位，再做视觉微调。
5. 内测运营辅助以读数据为主，不在本阶段扩展高风险后台写操作。

## 9. 推荐执行顺序

1. P0-1：认证和 API 客户端。
2. P0-2：课程列表和课程详情接入。
3. P0-3：练习页 cue 状态、进度保存和录音回听稳定。

5. P2-1：课程库完整搜索、筛选、收藏和继续学习。

7. P2-3：生词、学习记录和个人空间。
8. P2-4：个人上传、任务进度和私有课程。
9. P3-1：加载、空状态、失败重试和移动端。
10. P3-2：埋点、学习摘要、反馈、通知和内测运营辅助。

## 10. 开放问题

1. 正式生产短信服务选择和费用策略尚未确定。
2. 上传视频的 AI 转写、翻译和分句服务供应商尚未确定。
3. 内测用户规模、邀请方式和反馈渠道尚未确定。
4. 课程内容版权审核标准需要运营侧继续细化。
5. 录音是否在后续版本支持云端备份，需要在隐私策略明确后再评估。
6. P3 的埋点存储和看板方案需要在进入 P3 前确认。
