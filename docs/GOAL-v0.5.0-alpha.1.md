# EchoFlow v0.5.0-alpha.1 Goal

更新时间：2026-08-11

## 最终目标

> 一名受邀目标用户能够上传一段最长约 120 分钟的 MP4 英语视频；上传中断后在 7 天内继续；上传完成后原始清晰度视频可播放；MOSS 在后台生成唯一完整且时间准确的英文字幕；用户能在 5–10 分钟学习单元中逐句循环、录音、回听，并在第二次打开时准确继续；全流程在桌面和手机可完成，没有假进度、死按钮、跨用户访问、不可恢复数据或已知 P0/P1 Bug。

产品范围、架构边界和完整验收以 [EchoFlow V1 PRD](EchoFlow-V1-PRD.md) 为准。

## 决策门

```text
G0 成果保护与唯一主线
→ G1 契约、数据库、身份和安全
→ G2 长视频上传与可播放资产
→ G3 MOSS 与完整字幕原子发布
→ G4 真实播放器与影子练习
→ G5 生产加固与邀请制 Alpha
```

当前只允许执行当前 Gate 的任务。上一 Gate 没有证据通过时，不得用 Mock 或局部模块完成度进入下一 Gate。

G3 内部可按 G3-A（基础真实链路）、G3-B（跨分片交接可行性）和 G3-C（长媒体可靠性与容量）组织证据；这些阶段不构成新的 Gate，也不授权进入 G4。只有 G3 的完整退出条件有证据通过，才可继续下一 Gate。

## Goal 完成条件

- G0–G5 的退出条件全部有证据；
- 确认版 PRD、contracts、迁移、代码和运行行为一致；
- 真实 120 分钟黄金链路连续多轮通过；
- 至少一次验证 3 小时、8 GiB 架构上限；
- 双用户 owner 权限矩阵通过；
- PostgreSQL 恢复、Redis 重建、对象恢复和用户删除演练通过；
- 已知 P0/P1 为零；
- 5–10 名邀请用户中，多数可以无指导完成主路径；
- 发布、回滚、恢复和已知限制有可追溯证据；
- 版本从唯一 trunk 的可复现 Commit 创建。

## 非目标

- 公共课程市场、公开分享和推荐；
- 收藏、每日目标、连续打卡和排行榜；
- 翻译、双语字幕、手动字幕和字幕编辑器；
- 生词本、词典和笔记；
- AI 发音评分、自动纠音和考试题库；
- 多文件上传、多码率 HLS 和云端录音；
- 工作流导入 UI；
- 支付、社交和增长系统；
- Kubernetes、多地域和复杂高可用。

## Loop 规则

每个任务使用同一反馈环：

```text
任务合同
→ 实现
→ Verification 获取硬证据
→ 独立 Reviewer 判断
├─ 不通过：按失败证据返工
└─ 通过：绑定 Commit 并更新 State
→ Gate Evaluator 判断是否可以进入下一项
```

- 同时只允许一个核心纵向闭环处于集成状态；
- 调查、实现、验证和审核尽量分离 Context；
- Reviewer 默认只读，不边修改边批准自己；
- 同一失败原因连续三轮仍未解决时停止自动返工，交还给人；
- Flaky Test 不得通过重复运行掩盖；
- 审核证据必须绑定 Commit、环境和验证命令；
- 代码在审核后变化，原审核自动失效。

## 必须人工确认的边界

- 产品目标、范围和验收标准变化；
- 数据库破坏性迁移；
- 删除、覆盖、重写历史或清理 worktree；
- 创建外部仓库、推送到新的远程或更改可见性；
- 云资源采购、生产部署和域名切换；
- 真实用户数据迁移、批量删除和恢复切换；
- 安全、隐私、跨境和公开发布决定。

## 证据优先级

```text
可重复的自动化/数据库断言
> 真实接口和浏览器行为
> 日志、截图和运行记录
> Reviewer 综合判断
> Agent 自述
```

任务是否完成由证据决定，不由页面数量、代码行、测试数量、分支名称或版本标签决定。
