# EchoFlow 学习端 MVP PRD

更新时间：2026-07-25

版本：v0.1

文档类型：开发落地版 PRD

## 1. 背景与定位

EchoFlow 是一个英语视频影子学习平台。当前仓库已经具备学习端原型、运营后台骨架、NestJS API、异步媒体处理 Worker、共享契约、Prisma 数据模型和对象存储适配层。

本 PRD 聚焦学习端 MVP，目标是把现有原型推进到小范围内测可用状态，让成人英语自学者可以完成一个稳定的学习闭环：登录、找课、逐句练习、录音回听、保存进度、收藏课程、上传个人视频并生成私有课程。

### 产品定位

EchoFlow 是面向成人英语自学者的视频影子跟读工具。它不把重点放在考试刷题或社交展示，而是帮助用户把真实英语视频拆成可操作的句子训练单元，通过逐句播放、听写、跟读录音和回听，降低听说练习的启动成本。

### MVP 发布标准

内测可用。用户可以在真实账号下完成核心学习流程，关键数据可以同步，上传处理链路有明确状态反馈。高级 AI 反馈、商业化和公开内容生态不进入本阶段。

## 2. 目标用户与核心问题

### 目标用户

核心用户是成人英语自学者，典型特征如下：

| 用户类型 | 典型场景 | 关键诉求 |
| --- | --- | --- |
| 碎片时间学习者 | 通勤、午休、睡前学习 5 到 15 分钟 | 快速进入练习，不需要复杂准备 |
| 听说提升用户 | 能看懂字幕，但听不清、说不顺 | 逐句拆解、循环播放、跟读回听 |
| 兴趣内容学习者 | 想用旅行、日常、文化、职场视频学英语 | 内容有真实语境，难度和口音可筛选 |
| 自带素材用户 | 想练自己收藏或下载的视频 | 上传后自动生成私有课程 |

### 用户痛点

1. 真实视频太长，无法稳定坚持逐句听说训练。
2. 普通播放器缺少句子级循环、字幕视图、听写和跟读辅助。
3. 跟读练习缺少即时回听，用户很难判断自己是否真的说顺。
4. 用户收藏的视频不能直接变成结构化课程。
5. 学习进度、收藏和生词如果只在本地，很难跨设备继续学习。

### 产品机会

把视频按句子拆分，围绕每一句提供听、看、写、说的轻量闭环。平台精选课程解决启动内容问题，个人上传解决用户自带素材问题，账号同步保证持续学习。

## 3. MVP 目标与非目标

### MVP 目标

1. 用户可以通过手机号验证码登录，并在不同设备上同步学习进度、收藏和生词。
2. 用户可以浏览平台精选课程，按搜索、难度、主题和口音找到合适内容。
3. 用户可以进入课程详情，完成逐句播放、单句循环、倍速、字幕切换、听写、录音和回听。
4. 用户可以上传拥有学习和处理权限的视频，查看 AI 处理进度，并在完成后进入私有课程练习。
5. 产品可以记录并展示最小可用的学习记录、生词本和账户设置。
6. 团队可以通过核心指标判断内测是否有效：完成练习句数。

### MVP 非目标

1. 不做发音评分、音素级纠错或口语能力评级。
2. 不做 AI 教练、个性化长周期学习计划或自动复盘报告。
3. 不做公开视频分享、评论、关注或社区。
4. 不做支付、订阅、权益体系或商业化闭环。
5. 不做正式内容 marketplace。
6. 不把录音默认上传云端。MVP 中录音默认保存在本地，仅用于用户即时回听。

## 4. 核心指标

### 北极星指标

完成练习句数。

定义：用户在课程练习页中对一个字幕句完成至少一次有效练习动作后计为完成。有效练习动作包括播放原句、听写提交、录音完成或手动标记完成。MVP 优先使用“完成 cue”作为服务端进度的最小数据单位。

### 辅助指标

| 指标 | 定义 | 用途 |
| --- | --- | --- |
| 首课开始率 | 登录用户中进入任意课程练习页的比例 | 判断新用户是否能启动学习 |
| 单课完成句数 | 每节课程平均完成 cue 数 | 判断课程难度和节奏是否合适 |
| 录音使用率 | 完成练习句中包含录音动作的比例 | 判断影子跟读功能是否被使用 |
| 收藏转化率 | 进入课程详情后收藏课程的比例 | 判断内容吸引力 |
| 上传成课率 | 上传成功并生成私有课程的任务比例 | 判断个人上传链路质量 |
| 次日继续率 | 内测用户第二天继续完成练习句的比例 | 判断学习闭环是否有黏性 |

## 5. 用户旅程

### 旅程 A：新用户开始第一节课

1. 用户打开学习端。
2. 用户通过手机号验证码登录。
3. 系统进入首页，展示本周精选、继续学习入口和课程列表。
4. 用户可以搜索或使用难度、主题、口音筛选课程。
5. 用户打开课程，进入逐句练习页。
6. 用户播放第一句，查看双语字幕，开启单句循环或调整倍速。
7. 用户点击跟读录音，录完后回听。
8. 系统保存当前 cue、已完成 cue 和播放位置。
9. 用户退出后再次进入，系统从上次位置继续。

### 旅程 B：用户用个人视频生成课程

1. 用户点击上传视频。
2. 系统展示支持格式、大小限制和版权确认。
3. 用户选择 MP4 或 MOV 文件，勾选“拥有学习和处理权限”。
4. 系统请求预签名上传地址，并上传视频文件。
5. 系统创建处理任务，展示转码、语音识别、翻译与分句、发布等阶段进度。
6. 处理完成后，系统在个人上传列表展示私有课程入口。
7. 用户进入私有课程，使用与平台课程一致的逐句练习体验。

### 旅程 C：老用户继续学习

1. 用户登录后进入首页。
2. 系统展示继续学习卡片，包含课程标题、当前句子位置和完成进度。
3. 用户点击继续学习。
4. 系统进入上次课程和上次 cue。
5. 用户继续练习，新的完成句数和进度同步到云端。

| 个人课程列表 | `GET /api/uploads/lessons` | 返回用户上传生成的私有课程 |
| 上传任务刷新 | `GET /api/uploads/:uploadId/jobs` | 返回该上传关联的任务阶段 |

### 数据策略

1. 课程、字幕、进度、收藏、生词和上传任务使用服务端持久化。
2. 录音默认保存在浏览器本地 IndexedDB，不自动上传云端。
3. 个人上传课程默认 `private=true`，仅本人可见。
4. 平台精选课程必须经过运营审核和发布流程。
5. 前端所有跨端类型优先复用 `packages/contracts` 中的 Zod schema 和 TypeScript 类型。

## 8. 关键状态与异常

### 课程库

1. 加载中：显示页面级或区块级 loading。
2. 无结果：展示空状态，并保留搜索和筛选条件调整入口。
3. 接口失败：展示重试入口，避免白屏。
4. 未登录收藏：引导登录，登录后继续执行收藏动作。

### 练习页

1. 视频不可播放：展示错误提示，并允许用户继续查看字幕和练习文本。
2. 字幕为空：阻断进入逐句练习，提示课程仍在处理中或字幕不可用。
3. 麦克风拒绝：提示“未获得麦克风权限，你仍可继续不录音练习”。
4. 录音保存失败：提示检查浏览器存储空间，不影响课程进度保存。
5. 离线或保存失败：本地保留临时状态，恢复网络后重试同步。

### 上传

1. 未勾选权限确认：禁止上传并提示原因。
2. 文件类型错误：提示支持格式。
3. 文件超过 2GB：提示大小限制。
4. 预签名失败：提示稍后重试。
5. 上传中断：展示失败状态和重新上传入口。
6. AI 处理失败：展示失败阶段、错误信息和重试入口。

## 9. 验收标准

### 产品验收场景

1. 新用户可以用手机号验证码登录，进入课程库并开始第一节课。
2. 用户可以搜索和筛选课程，收藏课程后刷新页面仍保持收藏状态。
3. 用户可以进入课程，逐句播放、切换 cue、开启单句循环、切换倍速和隐藏视频。
4. 用户可以进入听写模式，输入内容后查看答案。
5. 用户可以授权麦克风录音，停止后立即回听。
6. 用户拒绝麦克风权限后，页面给出明确提示，并且仍可继续播放、听写和切换字幕。
7. 用户离开课程后再次进入，可以恢复到上次 cue 和播放位置。
8. 用户未勾选权限确认时不能上传视频。
9. 用户上传非视频文件或超过 2GB 文件时被阻断并看到明确提示。
10. 用户成功上传视频后，可以在个人上传页看到处理任务进度。
11. 上传处理完成后，用户可以从个人上传页进入生成的私有课程。
12. 移动端和桌面端都可以完成登录、找课、练习和查看上传任务。

### 技术验收

1. 学习端 TypeScript 检查通过。
2. 学习端单元测试通过，重点覆盖字幕解析、YouTube 链接解析、录音 Hook 和新增 API 适配逻辑。
3. 学习端生产构建通过。
4. API 契约变更后，相关 API、Web、Admin、Worker 构建和测试通过。
5. 录音流程在组件卸载时停止麦克风轨道，并释放临时音频 URL。
6. 上传链路不会在未确认权限、文件类型错误或文件超限时请求预签名接口。

## 10. 内测里程碑

### M1：学习端接入真实 API

目标：课程库、课程详情、进度和登录从静态状态迁移到 API。

交付：

1. 手机号登录流程。
2. 课程列表、搜索和筛选接入 `/api/videos`。
3. 课程详情和 cue 接入 `/api/lessons/:id`。
4. 进度读取和更新接入 `/api/progress/:lessonId`。

### M2：学习闭环可用

目标：用户可以稳定完成逐句练习。

交付：

1. 播放、暂停、cue 定位、单句循环、倍速。
2. 字幕标签、听写、录音和回听。
3. 收藏、生词和学习记录基础能力。
4. 移动端核心流程可用。

### M3：个人上传闭环

目标：用户可以把个人视频转成私有课程。

交付：

1. 文件校验和权限确认。
2. 预签名上传。
3. 任务进度展示。
4. 私有课程生成和入口。

### M4：内测稳定性

目标：具备小范围用户试用条件。

交付：

1. 关键异常状态补齐。
2. 核心指标埋点和内测数据看板。
3. 移动端和桌面端回归。
4. 内测用户反馈入口。

| `cue_played` | 用户播放 cue | lessonId、cueId、speed |
| `cue_completed` | 用户完成 cue | lessonId、cueId、actionType |
| `recording_created` | 用户完成录音 | lessonId、cueId、durationMs、本地保存结果 |
| `favorite_toggled` | 用户收藏或取消收藏 | lessonId、state |
| `upload_started` | 用户开始上传 | fileType、sizeBytes |
| `upload_job_updated` | 处理任务状态变化 | uploadId、jobType、status、progress |
| `private_lesson_opened` | 用户打开私有课程 | lessonId、uploadId |

## 12. 设计与体验原则

1. 第一屏直接服务学习，不做营销式首页。
2. 学习页优先保证播放器、当前句和字幕列表的扫描效率。
3. 录音、听写、循环等工具必须在当前句上下文内完成，不让用户跳出练习流。
4. 上传流程强调权限确认、进度透明和私有性。
5. 中文界面文案保持简洁，错误提示必须说明用户下一步可以做什么。

## 13. 开放问题

1. 正式生产短信服务选择和费用策略尚未确定。
2. 上传视频的 AI 转写、翻译和分句服务供应商尚未确定。
3. 内测用户规模、邀请方式和反馈渠道尚未确定。
4. 课程内容版权审核标准需要运营侧继续细化。
5. 录音是否在后续版本支持云端备份，需要在隐私策略明确后再评估。
